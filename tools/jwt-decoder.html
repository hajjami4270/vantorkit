Understanding JSON Web Tokens & Zero-Leak Security

Learn the mechanics of JWT authentication tokens, signature verification, and why offline decoders are essential for API security.

The 3-Part JWT Architecture

A JWT consists of Header (algorithm & type), Payload (user claims, roles, timestamps), and Signature separated by dots. The header and payload are simply Base64URL-encoded JSON, not encrypted.

Native Web Crypto Verification

Verification executes using the browser's hardware-accelerated crypto.subtle API. Your HMAC secret key is ingested directly into non-exportable cryptographic memory without external API calls.

Why Online Decoders are Risky

Pasting production JWTs or API signing secrets into third-party websites risks exposing session identifiers, email addresses, and HMAC keys to server logs, proxy caches, or malicious extensions.

Is my JWT or secret key stored anywhere?

No. All decoding and verification takes place strictly in volatile browser RAM. When you close the tab, all memory is immediately reclaimed by the garbage collector.

What does the "exp" timestamp claim mean?

The exp (Expiration Time) claim identifies the exact expiration time on or after which the JWT must not be accepted for processing. VantorKit humanizes this timestamp into local time and relative countdowns.

How do I verify Base64 encoded secrets?

Check the "Secret is base64 encoded" box under the secret key input. The tool will decode the Base64 bytes prior to importing the HMAC key into Web Crypto.

Can this tool verify RSA (RS256) or ECDSA (ES256) tokens?

The decoder parses all JWT algorithms (RS256, ES256, EdDSA, HS256, etc.) into readable claims. Built-in instant cryptographic verification is optimized for HMAC symmetric algorithms (HS256, HS384, HS512).
